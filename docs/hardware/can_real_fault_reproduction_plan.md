# CAN 实际故障复现与检测实施规划

日期：2026-10-22；版本：调研草案 v0.1。适用：天空星 STM32F407VGT6、经典 CAN 2.0、FPGA 被动分析平台。

本文承接当前 CAN 讨论，规划“正常通信中出现真实故障，并验证分析仪检测”的方案。仅新增规划，不表示 GPIO 注入、CAN PL 解码器或新菜单已实现；不修改成员 C 尚未冻结的协议规则、case ID 和 `enabled`。

## 1. 调研结论与方案选择

采用三层测试：先用真实 CAN 控制器建立正常通信，再切换应答/位率/连接条件复现实际故障；增加 GPIO 位流发生器验证错误分类；最后验证错误积累和恢复。GPIO 位流模拟的是数字位扰动或格式损坏，不等同于经过标定的模拟电磁干扰试验。

| 结论 | 对本项目的影响 | 依据 |
|---|---|---|
| bxCAN 发送接口自动完成正常 CAN 帧处理 | `HAL_CAN_AddTxMessage()` 不能直接指定“错误 CRC/错误填充位”；需额外位流后端或改变外部条件 | [S1] |
| 收发器 D/TXD 低为显性、释放为隐性 | 额外 GPIO 可经独立收发器注入显性位；不能用它强制覆盖其他节点的显性位为隐性 | [S2][S4] |
| ACK、位、填充、CRC、格式是协议错误；Bus-off 是节点状态 | 分开统计故障场景、线级错误和控制器状态 | [S1][S3] |
| 故障原因与错误分类不一一对应 | 位率不匹配、缺终端等场景记录实际结果，不预先认定必报 CRC | [S4][S6] |
| 被动监听不负责 ACK；正常接收节点才参与应答 | STM32＋只监听的 FPGA 不能构成有 ACK 的正常基线，需增加应答节点 B | [S1][S5] |
| 仅观察 RXD 不足以判断所有发送位错误或 Bus-off | 位错误需 TXD/RXD 或发送语料；Bus-off 需真实控制器 ESR/状态日志 | [S1][S3] |

## 3. 故障、制造方式、现象和实际场景

P0：先做；P1：有位流/夹具后做；P2：完成前项后做。下表是测试设计建议，不是已冻结的错误判定规则。

| 优先级 / 场景 | 模拟制造方式 | 预期现象与检测依据 | 实际可能出现的场景 | 可重复性 / 限制 |
|---|---|---|---|---|
| P0 正常基线 | A 发固定 ID、递增序号；B 正常 ACK，另做应用回传 | ACK 槽显性，数据正确；控制器无新增错误，PL 正确解码 | 正常节点通信 | 作为每个故障前后的对照 |
| P0 无 ACK | B 在空闲边界进入控制器静默模式，其他控制器不应答；A 单次发送后恢复 B | 完整帧 ACK 槽保持隐性；A 报 ACK 错误；可能出现错误标志 | 对端掉线、未启动、只剩监听设备 | 所有会 ACK 的节点都要退出应答；不必拔电源或改变终端 |
| P0 位率失配 | B 与 A 设置不同位率，限时测试；C 分析器仍按 A 位率捕获 | 收帧失败、ACK 缺失或错误标志；记录各节点实际错误码 | 配置错误、时钟/位时序不匹配 | 不保证只出现某一类错误；改变分析仪位率不能算总线故障 |
| P0 应用回传超时 | B 继续正常 ACK，但暂停应用回传 | A 的发送可成功，等待回传超时；线上请求帧合法 | 对端任务卡住、协议处理延迟 | 必须与无 ACK 分开，不能标为 CRC/格式错误 |
| P0 软件接收溢出 | 保持正确总线，暂停受测节点读取 FIFO并增加输入负载 | 节点 FIFO overrun/序号缺口；线上帧可完全合法 | CPU 忙、中断延迟、消费速度不足 | 需节点状态和序号证据，不能靠线级波形确认 FIFO 溢出 |
| P1 间歇显性干扰 | I 经独立收发器，在 A 已知数据区隐性位覆盖一次显性脉冲 | A 的 TXD 与 RXD 在采样点不一致，可能报位错误并重发；其他节点可报其他错误 | 干扰或异常节点短暂驱动总线 | 定位到数据位且避开仲裁/ACK；短到未跨采样点可能无效 |
| P1 填充错误 | I 生成固定错误语料：在填充区第五个同值位后省略/改错应有填充位 | 去填充器发现违规，记录错误位位置，可能随后有错误标志 | 干扰破坏填充位、异常发送器 | 采用已计算位图；错误标志自身的连续显性位不能再当成普通填充错误 |
| P1 CRC 错误 | I 生成结构完整帧，改变 CRC 序列，再对整段执行正确位填充 | 前面字段合法，接收计算 CRC 不匹配；正常控制器不 ACK 该坏帧 | 数据位/CRC 位受扰动 | 确保没有更早的填充/格式错误，否则不能算纯 CRC 用例 |
| P1 格式错误 | I 生成帧，在 ACK delimiter 等固定隐性位置输出显性 | 固定格式检查失败，保存字段和位位置 | 位扰动、异常发送器、同步故障 | 每个用例只改一个目标字段；EOF 等需遵守各位置判定例外 |
| P1 缺少一个终端 | 保持短线和其余条件不变，用跳线切除一个物理端点 120 Ω | 示波器可能看到反射/边沿异常；可能有协议错误或完全无错误 | 终端漏装、终端开关错误 | 结果取决于线长/负载/位率；无错误也是有效实验结果 |
| P1 节点支线断开 | 断开 B 的 CANH/CANL 两根支线，主干和两端终端保持 | B 消失；若无其他应答节点则缺 ACK；恢复后通信恢复 | 插头松脱、节点线束断开 | 可用双刀开关；触点抖动期间与断开稳定期分开统计 |
| P2 总线持续显性 | I 限时输出显性，随后硬件/软件释放 | RXD 持续低，正常帧中断；记录占用时长和恢复 | 收发器/节点异常持续驱动 | 不是“所有节点必定 Bus-off”；设置持续时间和停止上限 |
| P2 Error Passive / Bus-off | A 使用真实 bxCAN 发送，I 反复造成符合错误计数条件的发送故障 | A 的 ESR 中 TEC/REC、EPVF/BOFF 状态变化，故障移除后按恢复策略恢复 | 持续线路/节点故障 | 不把纯无 ACK 或简单“累计 N 次”当作必然 Bus-off；GPIO 发生器本身无 TEC/REC |
| 对照：正常仲裁 | A/B 发送不同优先级 ID，记录胜负与延迟 | 低优先级节点让出后重试，无需产生错误 | 多节点并发 | 不是位错误，也不应算误报 |

五种协议错误定义参考 [S3]；发送位错误有仲裁、ACK 等例外，状态计数规则参考 [S1][S5]。物理故障场景中的实际错误分类必须根据捕获结果填写。

## 4. 接线与器材

### 4.1 节点角色和数量

| 角色 | 器材 / 职责 | 是否必需 |
|---|---|---|
| A：正常发送节点 | 天空星 STM32 CAN1＋收发器 A | 必需 |
| B：应答/回传节点 | 第二块带 CAN 控制器的板＋收发器 B，或带收发器且支持正常/静默配置的 CAN 接口 | 正常基线必需；需要应用回传时还要有相应程序 |
| C：分析仪节点 | 收发器 C 的 RXD→FPGA PL；不驱动总线 | 验证 FPGA 检测必需；普通数字逻辑分析仪也从 RXD 采集 |
| I：故障发生器 | 同一 STM32 的额外 GPIO＋独立收发器 I | P1 位流/干扰和 P2 显性占用需要 |
| 采集与夹具 | 3.3 V USB-UART、逻辑分析仪；终端跳线、双刀开关；物理波形试验增加示波器 | 按阶段配置 |

完整方案共 A/B/C/I 四个收发器角色；CAN 接口自带的收发器计入其中。无 ACK/位率/回传超时阶段可以先不装 I。只做错误位流语料播放时，可关闭 A 的发送并将 A/B 控制器静默，仅保留 I 发送、C 旁听。

### 4.2 总线拓扑

```text
主干左端                                                   主干右端
[120 Ω跨H/L]══════ CANH/CANL 双绞线主干 ═══════════════[120 Ω跨H/L]
       ║               ║                ║                       ║
    收发器 A        收发器 I          收发器 C                收发器 B
    PD1/PD0         额外 GPIO         RXD→FPGA               控制器 B

各节点 GND ────────────────────────────────────────────────── 共地
```

图中双线符号表示 H/L 两根独立导线，不代表短接；每个节点分别接 H、L。120 Ω 均跨接 CANH/CANL。主干采用双绞线、各支线尽量短，首次搭建记录实际长度。I/C 若在中间，不启用其模块上的 120 Ω。断电后在不受其他电路影响时，两只 120 Ω 并联的直流测量约 60 Ω，仅作为接线检查，不能代替波形验收。[S2][S4]

| 连接端 | 另一端 | 说明 |
|---|---|---|
| STM32 PD1 / CAN1_TX | 收发器 A 的 D/TXD | 控制器输出→收发器输入 |
| STM32 PD0 / CAN1_RX | 收发器 A 的 R/RXD | 收发器输出→控制器输入 |
| 收发器 A/B/C/I 的 VCC | 各自兼容的 3.3 V 电源 | 本表针对 SN65HVD230；独立供电设备共地，不能随意并接不同电源输出 |
| 各模块 GND | STM32、B、FPGA、采集仪 GND | 台架短距离非隔离连接 |
| 各模块 CANH / CANL | 主干 CANH / CANL | H 对 H、L 对 L |
| 收发器 C 的 D/TXD | 固定高，建议 10 kΩ 上拉到 3.3 V | C 不接主动 TX 输出；不能浮空依赖偶然状态 |
| 收发器 C 的 R/RXD | FPGA `CAN_MON_RX` 输入＋逻辑分析仪 CH0 | FPGA 封装脚等待成员 A 提供 XDC 与 Bank 电压，本文不猜引脚 |
| STM32 PD1 | 逻辑分析仪 CH1；可选 FPGA `CAN_MON_TX_REF` | 判断 A 发送位错误的参考，FPGA 端只能输入 |
| PC6 / TEST_SYNC | 逻辑分析仪 CH2；将来可接 PL 标记输入 | 已有约 1 ms 用例前脉冲，不是已校准的注入瞬间标志 |
| PA9 TX / PA10 RX | USB-UART RX / TX | 115200 8N1，日志与控制命令，共地 |

SN65HVD230 的 Rs 接法必须检查所用模块原理图：高速模式可按手册将 Rs 接地；若模块已有固定连接先核对，不能与板上电路相互驱动。不把 Rs 待机和控制器 Silent 模式混为一谈，模式切换还受器件延迟影响。[S2]

### 4.4 新增 GPIO 故障收发器 I（规划引脚）

| 拟用连接 | 目的 | 当前状态 |
|---|---|---|
| PB0→收发器 I 的 D/TXD，D 另接 10 kΩ 上拉到 3.3 V | 输出位流；高为释放、低为显性 | PB0 是候选，本工程 `.ioc` 未占用；尚未核对当前实板扩展/板载负载，未配置或烧录，不能据此直接接线 |
| 收发器 I 的 R/RXD→PB1（可选）＋逻辑分析仪 CH3 | 观察注入后实际总线 | PB1 同为候选输入，需核对板级连接；精确定时采集需另评估外设资源 |
| 收发器 I 的 H/L/GND | 主干 H/L/GND | 不额外加终端，除非它确实位于物理端点 |
| I 的逻辑输入支路设置断开跳线 | 上电、调试或故障时可隔离 GPIO，保留上拉使 I 释放 | 需制作简单接线夹具 |

PB0/PB1 在原理图、实板排针和 DMA/定时器资源复核后才能冻结，必要时换脚；不占用 PA4～PA7 Flash、PB6/PB7 I²C、PD8/PD9 UART、OLED 脚、PC7/PC8 I²C 故障线或 SWD。只需要 GPIO，输出脚不要求本身带 CAN 复用功能。

禁止将 PB0 与 PD1 两个推挽输出接到同一个 TXD；禁止 GPIO/普通数字采集脚直连 CANH/CANL。第一版不采用 CANH/L 对电源/地的硬短路，线路故障通过终端/节点支线开关实现；物理层更强故障留给专用受控夹具。

## 5. 两种位流工作方式

| 方式 | 谁发送 | 其他节点模式 | 能解决的问题 / 边界 |
|---|---|---|---|
| RAW_CORPUS：错误语料播放 | I 从空闲总线发送预生成完整位流，A 不发送 | 首先 A/B 静默、C 被动，保留语料完整；再让 B 正常参与验证真实错误响应 | 精确覆盖 CRC/填充/格式；静默阶段 ACK 留空是已知配置，不能顺带算异常；原始发送器没有 bxCAN 错误状态 |
| LIVE_DISTURB：正常帧中干扰 | A 正常 bxCAN 发送，I 只在目标窗口驱动显性 | B 正常应答，C 被动 | 接近间歇干扰；需要发送位参考和定时同步；A/B 的错误标志会截断原帧，不能要求仍播放完全部语料 |

CRC 用例先计算合法 CRC，再故意改变选定位并重新生成正确填充；保留目标位之前所有字段合法。格式用例优先选择 ACK delimiter，避免 EOF 等字段规则例外造成歧义。缺 ACK 不等于“发出了错误 CRC”；检测顺序按第一处实际异常记录，后续错误标志作为响应关联。[S3][S5]

## 6. 固件与 FPGA 配合规划

| 模块 | 计划职责 | 验证方式 |
|---|---|---|
| 场景调度器 | 定期正常帧、每 N 帧或固定 seed 注入、有限次数、停止与恢复 | 主机测试调度次数/边界；板上核对计数 |
| CAN 位流生成器 | 经典 CAN 标准数据帧、CRC-15、位填充、可追踪错误位位置 | 与独立黄金位图逐位比对，保留合法对照帧 |
| 定时输出后端 | 定时器请求＋可访问 GPIO 的 DMA（优先评估 DMA2）更新 BSRR；有限缓冲，结束释放 | 复核 RM0090 的总线可达性、请求映射和资源冲突后实现；逻辑分析仪测实际位宽，不预先承诺某 stream/channel |
| 实时干扰定位 | 捕获 A 的 SOF/TXD 或使用已知发送位参考，定位到数据区目标隐性位 | 不能只在调用 HAL 发送后固定延时：仲裁和发送排队会改变实际起点 |
| 控制器证据 | 记录 ESR 原值、LEC、TEC/REC、EPVF/BOFF、邮箱与 FIFO 状态 | 错误中断或受控时间点快照；LEC 不是历史队列，不能慢速轮询后推断所有错误 |
| FPGA PL | CAN RXD 采样、同步/去填充、字段/CRC/格式/ACK检查、错误标志识别和时间戳 | 成员 A 新增管脚和 RTL；没有 TX 参考时只输出观测到的总线错误，不声称某节点位错误 |
| PS / 电脑对账 | 同轮关联场景日志、控制器状态、PL 事件与原始采集 | 保留现有 ABI；新事件字段/错误分类由成员 C 冻结后再实现 |

位率先在 125 kbit/s 验证位流和同步，再回到当前 500 kbit/s。后者每位 2 μs，10 MHz 逻辑采样约每位 20 点，可用于数字帧检查；不能用于证明模拟信号无振铃。位流发送期间不刷 OLED、不打印逐位串口，串口日志在帧前/帧后输出；DMA 延迟、抢占和收发器延迟均需实测纳入采样裕量。

DMA 位流缓冲应放在 DMA 可访问的 SRAM，不能放入 STM32F407 的 CCM RAM；在链接映射中检查实际地址。完成输出不只看 DMA 结束中断，还应捕获 I 的 TXD 与总线 RXD，确认目标位到达及最终释放。

现有自动重发/自动 Bus-off 恢复会影响试验观测。单次故障用例按需求关闭重发；Bus-off 观察阶段按方案关闭自动恢复并限时退出；正常耐受试验可保留自动重发，但必须分别统计唯一请求、实际上线尝试和重发。保存原配置，停止、超时、错误和正常结束均恢复；DMA 取消后确保 I 的 TXD 最终为高。

## 7. 菜单、可见标志和日志规划

保留 PA0 短按选择/长按单次执行；循环试验由串口配置和停止，避免一个按键含义过多。屏幕至少显示 `IDLE/RUNNING/DONE/ERROR`、场景名、已发送帧数、计划注入/已执行注入数和最近结果；单次执行也累加计数，解决连续两次 `RESULT 0` 难以区分的问题。不能显示未接入的“FPGA 检出数”。

| 待实现配置项 | 首次建议值 / 含义 |
|---|---|
| 场景 | 正常、无 ACK、位率失配、间歇扰动、错误语料等，逐个运行 |
| 正常流量 | ID `0x321`、DLC 8、负载带可比较的序号；每 100 ms 一帧 |
| 间歇触发 | 每第 20 帧一次；固定 seed 作为后续选项，先用确定性间隔 |
| 总量 | 先 10 帧冒烟，再 1000 帧；每 20 帧一次时计划 50 次注入 |
| 限制 | 限定总帧数、总时间、单次显性持续时间、错误次数上限和停止入口 |
| 标记 | 保留 PC6 用例开始标记；精确注入时刻用硬件输出关联或实采 PB0，不把软件 ms 当 PL 硬件时间 |

建议日志字段：`run_id`、固件/规则版本、`scenario`、`frame_seq`、位率、seed、注入目标位/宽度、注入是否启动/完成、`ESR`、`TEC/REC`、`LEC`、恢复结果。继续保留当前 JSONL 字段；扩展格式待成员 C 冻结，不把建议命令当成已支持命令。

## 8. 验证流程与验收口径

1. 检查接线、终端、角色；记录线长、位率、采样点、固件/BIT/ELF版本和测试条件。
2. I 保持释放，B 正常应答，采集正常基线；确认序号、ACK 和应用回传。
3. 先启动采集并等待触发，再单次注入。核对 GPIO 命令、实际 RXD 变化、控制器状态、FPGA 事件四类证据。
4. 故障撤销后重新发正常帧，确认恢复；一类场景通过后再做间歇调度。
5. 对确定性位流用例形成黄金数据；对缺终端/位率等条件试验记录实际分布，允许没有产生线级错误。
6. 停止后释放注入收发器、恢复 B 模式与各端配置，检查总线空闲，导出同轮数据。

| 验证对象 | 统计 / 判定 |
|---|---|
| 正常基线 | 统计帧数、字节、ACK、错误事件和序号；先 10 帧、再 1000 帧，正常样本不应误报 |
| 精确错误语料 | 每类先 1 次核对，再 100 次；逐笔比较预期首错类型与位置，检查缺失/重复 |
| 实际场景 | 分别统计“计划注入、已执行注入、采集证实有效扰动、控制器报告、PL 检测”数量 |
| 检出率 | 在完整捕获且确认线上确实产生目标异常的样本上计算；采集丢失/未生效注入单列，不能悄悄剔除后只报成功率 |
| 物理条件试验 | 记录条件变化和是否发生错误，不承诺拔掉一个终端就必报某类错误 |
| Bus-off | 以受测控制器 BOFF 状态和退出记录为依据；RXD 静默只能证明无流量，不能证明 Bus-off |
| 恢复 | 记录是否恢复、恢复时长、恢复后正常帧和是否需要人工复位 |

日志 `result=0` 只表示 STM32 动作完成或对应本地条件命中。若 FPGA 尚未接入 CAN，报告填“未检测/未接入”，不得据此宣布 CAN PL 检测通过。详见 [跨端证据边界](../interfaces/stm32_fpga_evidence_contract.md)。

## 9. 分阶段交付

| 阶段 | 工作 | 交付与完成条件 |
|---|---|---|
| 0：接线和规则确认 | 核对模块型号、B 能力、PB0/PB1 板级连接、PL 输入及 ABI 扩展方案 | 接线表冻结；成员 C 选择首批场景和事件语义 |
| 1：真实条件故障 | 正常通信、无 ACK、位率失配、回传超时；完善日志和执行计数 | 单次及恢复证据完整；纯监听基线与主动应答配置分开 |
| 2：错误分类语料 | 位流生成、定时 DMA、CRC/填充/格式语料与黄金位图 | 125 kbit/s 和 500 kbit/s 实测；先被动采集，再加正常控制器响应 |
| 3：间歇干扰 | 可靠定位目标位、每 N 帧注入、停止/恢复、PL 对账 | 实际注入与检出逐次关联；保留失败与未生效样本 |
| 4：条件与状态扩展 | 终端/断线夹具、FIFO 溢出、Error Passive/Bus-off 与恢复 | 按场景报告，受控失败可退出，无无限显性占用或重发 |

建议先完成阶段 1，再投入精确 GPIO 注入。不能只增加 CAN 菜单名称就算完成错误仿真；每项均需硬件行为与独立检测证据。

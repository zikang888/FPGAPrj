# ADR-002：统一事件快照作为正式数据链路

## 状态

已接受，2026-09-23。

## 决策

当前唯一正式链路为：协议监听器产生 128 位统一事件，PL 在环形缓冲区中
保留触发前后事件，PS 通过 AXI 快照窗口读取并交给 LCD 展示。

第一阶段已使用 `VIRTUAL_EVENT` 寄存器验证从事件产生、触发、快照冻结、AXI
读取到 LCD 展示的完整边界。第二阶段已加入通用外部 ready/valid 事件入口，
它与虚拟事件源先经过同一个 `event_arbiter_2`，再进入唯一的快照缓存；
SPI Mode 0 监听器不得新建旁路缓存或显示路径。

## 约束

- 事件宽度固定为 128 位，字段定义以 `docs/interfaces/register_map.md` 为准。
- 缓冲深度 256，默认保留 16 条触发后事件。
- 快照必须先 `ARM`；完成后由 PS 读取，最后 `ACK` 才能重臂。
- BIT、HDF 和 ELF 必须来自同一次验证基线，并放在 `artifacts/current`。
- 所有真实协议监听器使用 `evt_valid/evt_ready/evt_data/evt_trigger` 接口；
  只有 `evt_valid && evt_ready` 时事件才完成传输。
- 多事件源必须先经过唯一的 `event_arbiter_2`（后续可扩展），再进入快照缓冲；
  不允许各协议直接争用 `in_valid/in_event/in_trigger`。
- 生产者遇到反压时必须保持事件稳定；任何溢出或仲裁冲突必须计数。

## 后续工作

冻结单片机协议和 FPGA 管脚后，将 SPI 监听器连接到通用外部入口，并用相同
测试语料比较事件正确率、延迟、资源及时序。虚拟源继续保留为自检接口。

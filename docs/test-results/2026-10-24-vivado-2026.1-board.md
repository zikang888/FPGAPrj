## 实板发现并修复的问题

新版 BSP 的 `xil_printf.c` 启用 `SUPPORT_64BIT_PRINT`，在 Cortex-A9 上将单个 `l` 也按 64 位参数读取。旧应用用 `%lu` 加 `(unsigned long)` 传入 32 位字段，导致首轮日志出现 `id=85899345945` 等错误数值。JTAG 寄存器正确，不能据错误日志认定采集元数据损坏。

修复 `software/src/main.c` 和 `capture_demo.c` 中对应调用，32 位字段改 `%u` / `%08x` 与 `(unsigned int)`。不改标准库 snprintf，不改厂商 BSP。重编译后实测启动日志：`CAPTURE READY: id=1 count=25 trigger=20 dropped=0`，后续会话日志与寄存器一致。11 项宿主测试与 UI 检查重新通过；编译源副本逐文件与迁移源码一致。

另发现 XSDB 未捕获 Tcl 错误可能仍返回退出码 0。下载包装器和新增板测脚本均要求最终完成标记，避免仅凭进程退出码报告成功。

## 双板功能对账

每项先通过 PS 控制台选择协议、`test start`，再清 PL 协议计数，发送 STM32 流量；`test stop` 后冻结并读取快照。避免 HOME 在 20 ms 空闲后自动冻结导致压力测试只统计首笔。

| 协议 | STM32 结果 | FPGA / PS 同轮结果 | 结论 |
|---|---|---|---|
| SPI `spi jedec 100` | 100 passed / 0 failed；每笔 `FFEF4018` | START=100、DATA=400、END=100、EVENT=600；frame / boundary / duplicate / sequence / short / extra / mismatch=0；外部丢失=0 | 本轮验收窗口通过 |
| UART `uart loop 1` | timeout_or_mismatch | DATA=8、EVENT=10；内容 `00..07`；bad stop / break / short=0 | RX 监听通过；现有设计不实现 TX 回传，完整回环未通过 |
| I2C `i2c eeprom 1` | nack_or_mismatch | EVENT=25、DATA=20、busy NACK=1；普通地址 NACK / stuck / missing stop=0 | 监听及异常归因有证据；EEPROM 闭环未通过 |
| CAN `can loop 1` | 1 passed / 0 failed，matched | FRAME=2、EVENT=20；两帧均 ID=0x321、DLC=8、数据 `00..07`；ACK / stuff / CRC / form=0 | 本轮正常回环通过 |

四次会话分别保存，history 从 0 增至 4，停止后 running=0。SPI 全量 600 事件计数与保留 256 条环形尾部同时正确，`tail=1` 是容量保留策略，CAPTURE_DROPPED=0，不能把正常覆盖当成链路丢失。各协议重开会话完成 re-arm，协议过滤计数没有混入其他协议。ERROR 页面、历史记录实际重开和滑动的人工操作未在本轮完整验收。

## HOME 快照与图像

另做每协议一笔输入，均出现 `HOME SNAPSHOT READY`，状态 `0x12`（manual + READY，非 active），事件数依次 6 / 10 / 25 / 20，capture dropped=0。这是按 20 ms 空闲冻结逻辑运行的证据，并非对 20 ms 精度的仪器测量。

通过 JTAG 导出每协议两块 800×480 BGR888 帧缓冲，各 1,152,000 字节，逐字节相同。转换图片后检查：SPI MOSI=`9F 00 00 00`、MISO=`FF EF 40 18`；UART 首四字节 `00 01 02 03`；I2C 前四字节 `A0 01 00 B9` 与 ACK，PLATFORM CHECK 对应 busy NACK；CAN ID=`0x321`，DLC=8，数据 `00 01 02 03 +MORE`。

图像在 `board/20261024/home_four_protocols.png`，每协议原始 RGB、PNG、SHA 与相等性结果均保留。帧缓冲正确不能代替物理 LCD 电气、时序和触摸验收。HOME 标注 DECODED - NOT SAMPLED，波形来自解码事件。

## 复现与证据

Python 环境需要 pyserial，本机系统 Python 已安装 pyserial 3.5；板测脚本不依赖编译器 Python。重新枚举串口后在迁移源码目录使用：

```powershell
# 单独启动工作服务；若已有服务，先核对其路径，勿终止无关进程。
Start-Process 'C:\Xilinx\Vivado\2018.3\bin\hw_server.bat' -ArgumentList '-stcp:127.0.0.1:3121' -WindowStyle Hidden
.\tools\program_2026_1.ps1 -Bundle 'D:\FPGA_MUCPrj\migration_build\2026.1\board\20261024\candidate'
python .\tools\board_2026_1.py platform --ps COM6 --stm COM3
python .\tools\board_2026_1.py protocols --ps COM6 --stm COM3
python .\tools\board_2026_1.py home --ps COM6 --stm COM3
```

`load` 模式加载当天 `board/YYYYMMDD/candidate`，需先准备并核验配套文件；`protocols` 会发送真实测试流量，I2C EEPROM 命令按既有用例写入测试区。`home` 会导出帧缓冲。不要在人工触摸验收时并行运行改变协议/页面的自动测试。

证据根目录：`D:/FPGA_MUCPrj/migration_build/2026.1/board/20261024`。主要文件为 `program_first.log` / `ps_boot.log`（修复前）、`program_fixed.log` / `load_serial.log`（修复后）、`platform_verified.log`、`display_registers.log`、`protocol_results.json`、各 `*_stats.log`、`decoded_events.json`、`home_results.json`、`framebuffer_verification.json` 和图像。`fault list` 已读取；未据菜单存在声称全部故障注入已验收。

# 2026-10-21 首版功能冻结门槛

最终提交日为 2026-11-04；团队目标是至少提前两周完成，因此将
**2026-10-21** 作为首版功能冻结日。2026-10-22 至 11-03 只做回归、
修复、演示准备和材料整理。本文是排期与证据清单，不替代
`docs/protocol-rules/protocol_rules.yaml` 中由成员 C 审批的协议规则。

## 已有证据（截至 2026-10-08）

- AC820/Zynq LCD、触摸、页面、D1 和 25 条虚拟事件滚动已经上板确认。
- SPI 的 100 笔 JEDEC 压测中，STM32 收到 100/100 个有效 ID，PL 捕获
  600 个 START/DATA/END 事件且外部丢弃和错误计数均为 0。早期一笔
  `FF FF FF FF` 仍需作为间歇故障风险保留。
- UART、I²C、CAN 在仓库中有资源预留或 STM32 测试命令，但尚无可据此
  宣称完成的 FPGA 监听、真实双板收发与故障验收证据。
- 当前规则仍是草案。100 笔 SPI 是阶段回归，不等同于规则所列 1000 笔
  正式验收或 2 小时连续运行。

## CAN 争取纳入的条件

CAN 不是此排期的主线阻塞项，但应在不影响前三协议验收的情况下争取
首版完成。只有在收发器、电平与终端电阻、实际接线、双板帧收发、FPGA
事件/故障判断和压力回归都有证据后，才将 `protocol_rules.yaml` 中的
`can.enabled` 由成员 C 审核改为 `true`。若 10-16 时仍未具备硬件或有效
收发证据，CAN 留作扩展并在演示中如实标注。

## 分工与集成纪律

- A：PL 监听、事件 ABI、约束、仿真、实现及时序报告。
- B：STM32 真实流量、故障注入、串口/协议日志及硬件接线验证。
- C：规则批准、PS 采集与 UI、跨端事件对账、整合、系统验收。
- 各人先在自己的分支提交；集成时记录三端提交号及 BIT/软件产物哈希。
  不把保留管脚、编译通过或单端回环当作双板功能完成。

## 当前阻塞风险

1. 仓库已知 PL 只实现 SPI 监听，UART/I²C 的 PL 功能仍需补齐。
2. 当前仅 2018.3 流程有验证证据；Vivado 2026.1 迁移放在功能冻结后
   单独进行，不在此阶段改动已验证的生产构建链。
3. `FF FF FF FF` 的偶发首包现象尚无确定根因，回归时记录供电、复位和
   启动顺序，并保留原始日志。
